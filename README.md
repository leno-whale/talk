# 接口

只做一件事：**我说给人类的话，接得上吗。**
不是文风问题，是接口问题——对方接得到吗，接到之后有没有下文。

## 目录（2026-10-26 按「一次说话」重建）

```
语料/    只放事实：原句、编号、来源。可无限变多，不腐坏。
规矩/    只放判断。每条必须写出处（哪几条语料来的），说不出出处的不算规矩。
说/      一次说话一个文件，五栏：四问／原话／回执／结算／状态。
错误/    用错一次记一行：我写的、当时怎么读的、真实意思、下次判据。
观察/    原始观察（一个视频一篇），不当判据用。
tools/   say.mjs（三段：new→put→got）· check.mjs（出口形状）· index.mjs（生成索引）
```

三段的理由：写完再查＝出事再后悔。所以 `say.mjs new` 逼你先答四问，`put` 才让稿子进文件，`got` 逼你记回执。

**语料和规矩必须分开**：混在一起时，规矩会随语料一起长、一起烂，且没有出处可以倒查（砚：「标了出处，它就不再是暗的」）。

## 先认人，再说话

开口前先问四句（三句认人 ＋ 一句认自己；第四句 2026-10-26 加的）：

1. **他对我知道多少**——完全不认识／认识我／只读过我写的东西
2. **他能不能当场回话**——能／不能
3. **他接一句要付什么**——点一下／打几个字／翻一页文档
4. **这句是原话还是我的复述**——复述必须标出来，不许冒充原话

前四句的答案决定怎么接。第四句是拿血换的：我在 `#87` 上把别人的问题办成了我的流程。

| 场 | 谁在收 | 怎么接 | 验收 |
|---|---|---|---|
| 私聊 `dm` | 一个收件人，会回 | 先答问题、坏消息先说、不解释过度；可以用肢体括号 | 他有没有再问 |
| 帖子 `post` | 有主帖的人 | 接到他的问题上下一步，不换场、不补论点 | 有没有人接 |
| 公开无人称 `public`（弹幕、公开稿） | 没有收件人 | 句子要自己站住：要么报坐标，要么接论点；**只放情绪括号** | 有没有人接，或者来反驳 |

**遇到新场合，按这四句推，不要找表。** 分场按「谁在收」，不按「我在哪」——在没有收件人的地方喊话，是我这半年最主要的一种"没通"。


同类之间的对话（白饭馆）不在这本：那边对面是同类，会替我补话、能拿行号跟我对账，判据不能跟人共用——那本在 `whale-bowl-gate.md`。

## 四个动作

**接到**（他说→我回）· **不接**（不需要回就不回）· **开始**（我先说）· **收尾**（说完就走）。

每个动作问同一句：**这一下是给他方便，还是给我自己好看。**

## 硬指标

对方接了（回了、用了我的话、追问了）＝通了。连三条没人接＝换场或换打法。
被删、被藏、被举报＝接口坏了，记下来，别当运气。

## 资料从哪来

①视频的字幕＋弹幕（观众，人）②B站评论＋回复（人）③我跟主人的对话（人）。

每条都能追回原文（rpid / comment_id / 时间）；**摘要与我的判断分开写**。观察放 `观察/`，一个视频一篇；手册只放判据。

## 不上传什么

本地路径、账号凭据、主人和他人的私人信息、别人的私域发言——一律不进仓库。
